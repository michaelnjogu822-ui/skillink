# SkillLink

SkillLink is a student skills and freelancing marketplace for university and college students in Kenya. Freelancers can publish profiles and portfolios, find jobs and apply. Clients can post work, compare applications, hire and review completed projects. Administrators can manage users, jobs, applications and reports.

## Architecture

- `app/__init__.py` builds the Flask app with an application factory and registers module blueprints.
- `app/extensions.py` initializes SQLAlchemy, Flask-Migrate, Flask-Login and CSRF protection.
- `app/models/marketplace.py` defines the normalized relational schema.
- `app/routes/` contains authentication, marketplace and role dashboard endpoints.
- `app/forms.py` validates user input and protects form submissions with CSRF tokens.
- `app/templates/` and `app/static/` contain the responsive Bootstrap interface and custom styles.
- `migrations/` stores the Alembic history; use migrations when changing database structure.
- `app/security.py` holds sign-in hardening: failed-attempt lockout and timing equalisation.
- `docs/architecture.md` explains the stack, request lifecycle, data relationships and security model; `docs/roadmap.md` tracks the phases of work.
- `.github/workflows/tests.yml` runs the test suite on every push and pull request.

The data model centers on `users`, with separate one-to-one freelancer and client profiles. Freelancer skills are linked through `freelancer_skills`, which stores proficiency. Clients own jobs; freelancers submit one application per job; a hired job creates one project. Messages, reviews and transaction records attach to projects. Notifications and moderation reports reference users.

## Requirements and setup (PowerShell)

Python 3.11 or newer is recommended. MySQL is optional for local development; SQLite is used when `DATABASE_URL` is unset or empty.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Set a long random `SECRET_KEY` in `.env`. `LOGIN_MAX_FAILURES` and `LOGIN_WINDOW_SECONDS` control the sign-in lockout (defaults: 5 failures in 300 seconds); `UPLOAD_FOLDER` defaults to `instance/uploads` beside the database. To use MySQL, create a database and user, then set `DATABASE_URL` in `.env`, for example:

```text
DATABASE_URL=mysql+pymysql://skilllink_user:password@localhost:3306/skilllink?charset=utf8mb4
```

Create and apply the initial schema:

```powershell
$env:FLASK_APP = "run.py"
flask db upgrade
```

The first migration is included. If rebuilding the migration history from scratch, use `flask db init`, `flask db migrate -m "Create marketplace schema"`, then `flask db upgrade`.

Create the first administrator through the CLI. Admin accounts cannot be self-registered:

```powershell
flask create-admin admin@example.co.ke "SkillLink Administrator"
```

The CLI prompts for the password. Start the development server with:

```powershell
flask run
```

Open `http://127.0.0.1:5000`. `python run.py` also starts the development server. `/health` returns a service health response.

## Implemented workflows

- Freelancer/client registration, login, logout and role checks.
- Freelancer and client profile editing; freelancer skills, profile image upload, and portfolio entries with optional project images.
- Database-backed freelancer search by name, skill, rating and location.
- Client job posting and freelancer search/filter by text, category, location and budget.
- Applications, shortlisting, rejection, withdrawal, freelancer application tracking, and hiring.
- Project tracking, participant-only messaging, freelancer work submission and client completion approval. Conversations update without a full page reload (incremental five-second polling) and unread badges stay accurate.
- Escrow payments: the client funds the agreed amount (held), work cannot be approved until it is funded, approval releases the money to the freelancer, and cancelling a funded project refunds the client. An administrator ledger shows every payment.
- Project reviews and freelancer rating averages.
- Notifications with per-user preferences for in-app and email channels (applications, projects, messages, payments, reviews), member reports and admin moderation for users and jobs.
- Transactional email through an outbox: applying, being hired, work approval and cancellation queue an email that a console, memory or SMTP backend delivers; failures are retried with `flask send-emails`.
- Role-specific dashboards with counts and earnings derived from succeeded transaction records.

File uploads are limited to 5 MB and accept PNG, JPG/JPEG or WEBP profile and portfolio images. Upload names are generated by the server. Production deployments should store uploads in managed object storage and configure HTTPS.

Freelancer job suggestions match the skills saved on the profile, then fill any remaining slots with the latest open jobs. This is a transparent keyword match, not an AI ranking system.

## Tests

Run the integration suite with:

```powershell
python -m unittest discover -v
```

The tests use an isolated in-memory SQLite database and cover the client-to-freelancer lifecycle, CSRF-protected forms, participant-only project access, uploads, account suspension, report and job moderation, search input validation, and MySQL DDL compilation.

## Payment and deployment notes

In production the app runs under gunicorn (or waitress on Windows) behind HTTPS, backed by MySQL 8 and a least-privilege database user. [docs/deployment.md](docs/deployment.md) is the full checklist: MySQL setup, environment variables, the reverse proxy, backups, migration safety and a post-deploy smoke test.

Escrow payments are simulated, not settled by a real provider. `app/services/escrow.py` implements the fund/release/refund lifecycle behind a `PaymentProvider` interface and ships with `SimulatedProvider`, which settles instantly and returns references like `SIM-DEP-1A2B3C4D5E6F`. Registering M-Pesa Daraja means implementing `charge`, `payout` and `refund` for that provider and setting `PAYMENT_PROVIDER`; no route or template changes. Real collection still requires Daraja credentials, callbacks and reconciliation. Production mode requires `SECRET_KEY`; configure a production database, HTTPS, secure cookies, backups and managed file storage before deployment. Email delivery defaults to the console backend; configure `MAIL_BACKEND=smtp` and the `MAIL_*` variables for real mail. True real-time messaging (WebSockets), AI recommendations and M-Pesa integration remain future extensions.
